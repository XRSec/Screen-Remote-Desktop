# Android parity boundary

Use Android to preserve product meaning where the platforms share a remote Android device, not to copy Compose structure.

Inspect the corresponding `../Screen-Remote/app/src/main/java/com/screen/remote/android/` path for:

- ADB connection candidates, preflight, state transitions, timeouts, and error meaning;
- scrcpy channel order, metadata, media negotiation, control semantics, and cleanup;
- management capabilities and data fields for device info, utilities, files, apps, processes, forwarding, and commands;
- shared dadb helper commands and record meanings.

Implement native SwiftUI navigation, window behavior, menus, sheets, keyboard interaction, drag/drop, file panels, and macOS lifecycle. Preserve terminology and user outcomes, but adapt density and interaction to macOS.

When parity is incomplete, label the limitation accurately. Do not claim audio playback, control routing, companion-backed notifications, messages, or photos until a real data path exists.
